# AI 블로그 자동화 — 엔지니어링 쇼케이스

API가 사라진 Tistory에 **사람 개입 없이 매일 글을 발행**하는 시스템을 만들고 운영한 기록입니다.

> 이 저장소는 **아키텍처와 설계를 공개하는 쇼케이스**입니다. 전체 구현(특히 봇 탐지 대응 등 민감한 부분)은 비공개이며, 코드 수준의 상세는 [전자책](https://kwonseongjae.github.io/ebook-landing/)에서 다룹니다.

## 한 줄 요약

**글을 만드는 건 쉬웠다. 사람 없이 매일 안 죽게 발행하는 게 진짜 문제였다.**

"AI 블로그 자동화" 자료는 대부분 *글 생성*에서 끝납니다. 이 프로젝트는 그 다음 — **브라우저 자동 발행을 24/7 안 죽게 운영**하기까지의 엔지니어링을 다룹니다.

## 배경: Tistory는 2024년 2월에 Open API를 닫았다

API가 있을 땐 HTTP 요청 한 번이면 글이 올라갔습니다. 이제는 사람이 브라우저에서 하는 모든 동작(로그인 → 에디터 → 이미지 → 발행)을 코드가 대신 눌러야 합니다. 그리고 바로 여기서 거의 모든 자동 블로그가 멈춥니다.

## 시스템 구성 (개요)

```
수집/생성(AI)  →  SEO  →  발행 엔진(브라우저)  →  색인 신청  →  운영/모니터링
   콘텐츠 엔진       제목·스니펫    안정화가 핵심        구글/네이버      스케줄·큐·알림
```

- **콘텐츠 엔진** — LLM으로 검색 의도에 맞는 글 생성(검색어 타겟팅·SEO 스니펫)
- **발행 엔진** — 헤드리스 브라우저로 에디터를 조작해 발행
- **★ 안정화** — 세션/2FA, 1회용 임시 프로필, 멈춤 자가복구, 내구성 큐 *(이 프로젝트의 핵심)*
- **운영** — 스케줄링, 발행 큐, 색인 신청, 모니터링·알림

## 자동 블로그가 멈추는 6가지 지점 (그리고 구조적 해결)

| 멈춤 | 땜빵(실패) | 구조적 해결 |
|---|---|---|
| 세션 만료 → 재로그인 2FA 루프 | 매번 재로그인 | 암호화 쿠키 저장소 + 세션 keepalive로 재로그인 회피 |
| 봇 탐지(캡차) | 수동 개입 | 자동 대응 파이프라인 *(상세 비공개)* |
| 프로필 락 충돌(`Connection refused`) | 재시작 | **1회용 임시 프로필**로 공유 상태 버그 클래스 제거 |
| 발행 중 무한 멈춤 | 타임아웃만 | 하드 타임아웃 + 워치독 + 락 잔여물 정리 자가복구 |
| 중복 발행 | 수동 삭제 | 발행 전 **멱등 가드** |
| 콘텐츠 고갈 | — | 에버그린 토픽 풀 + 자동 확장 |

핵심 교훈: **워치독·재시작 같은 땜빵은 같은 버그를 다른 얼굴로 되돌린다. 버그 클래스 자체를 없애는 설계가 답이다.**

## 정직한 현실

이 시스템이 운영하는 블로그의 **실수익은 (현재) 0원**입니다. 트래픽의 대부분이 수동으로 쓴 글 몇 개에서 나오고, 자동 생성 글의 검색 색인은 진행 중입니다. **"안 죽게 만드는 것"(엔지니어링)과 "그게 돈이 되는 것"(트래픽·SEO)은 완전히 다른 싸움**이라는 게 가장 큰 배움이었습니다.

## 라이선스 / 고지

브라우저 자동화는 각 플랫폼의 이용약관·정책에 영향을 받습니다. 이 저장소의 내용은 **교육·엔지니어링 목적**이며, 적용은 본인 책임입니다.
