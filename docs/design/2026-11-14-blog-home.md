# 기술블로그 대문 설계

작성: 권성재 · 상태: 제안 · 선택 방향: 학습 기록과 공개 코드를 함께 보여주는 혼합형

## 목적과 선택

방문자가 작성자와 글의 성격을 이해하고, 최근 학습 기록과 실행 코드로 이동하도록 한다. 학습 기록이 쌓이면서 자기소개서와 경력 설명의 근거로 연결되게 한다.

| 검토한 방향 | 장점과 한계 | 판단 |
|---|---|---|
| 글 중심 | 읽기에 집중하지만 작성자와 코드 연결이 약하다. | 대안 |
| 포트폴리오 중심 | 작성자 소개가 선명하지만 현재 공개 글 2편으로는 소개의 비중이 크다. | 대안 |
| 혼합형 | 짧은 소개 다음에 실제 글과 코드를 배치한다. | 사용자 선택 |

## 대문 구성

블로그 이름은 **권성재의 기술노트**로 통일하는 안을 제안한다. 이는 새 명칭에 대한 제안이며 아직 적용하지 않았다.

- 소개 제목: **직접 실행하고, 이해한 것을 기록합니다.**
- 소개 문장: **Python에서 시작해 코드와 문제 해결 과정을 쌓아갑니다.**
- 소개 링크: **실습 코드 저장소**를 주 링크로, **GitHub 프로필**을 보조 텍스트 링크로 표시해 목적지를 구분한다.
- **최근 기록**에는 티스토리의 실제 최신순 제목·발췌 두 줄·발행일·분류를 표시한다. 원고별 코드 링크는 기존 본문을 이용한다.
- 대문의 반복 카테고리 버튼을 없애고 **주제별 기록**에서 탐색하게 한다. 상단 주제 메뉴는 빠른 이동용으로 유지한다.
- 카테고리는 실제 집계가 0인 항목만 방문자 목록에서 숨긴다. 집계를 확인할 수 없으면 항목을 유지한다. 전체 글 연결은 항상 제공하고 관리 카테고리는 보존한다. 주제가 하나뿐일 때는 큰 박스로 강조하지 않고 짧은 목록으로 표시한다.
- 오른쪽의 **기록 원칙**에는 실행 코드·확인 결과·공식 출처·적용 한계를 간결하게 설명한다. 홈의 최근 글 위젯은 본문 목록과 중복되므로 숨기며, 개별 글에서는 유지한다.

데스크톱:

```text
권성재의 기술노트                              글 검색
전체 글    주제별 보기    GitHub 코드    RSS
------------------------------------------------------
직접 실행하고, 이해한 것을 기록합니다.   주제별 기록
소개 한 문장                           실제 분류와 글 수
실습 코드 저장소 / GitHub 프로필
                                      기록 원칙
최근 기록                             코드·결과·출처·한계
최신 글 제목 / 발췌 / 날짜·분류
다음 글 제목 / 발췌 / 날짜·분류
```

모바일 순서: 이름 → 검색·메뉴 → 짧은 소개와 GitHub 링크 → 최근 기록 → 주제별 기록 → 기록 원칙. 작성자와 코드 연결이 글 목록 아래로 밀리지 않게 한다. 검색 입력은 유지하고 소개의 여백과 문장 길이를 줄인다. 390px 폭에서 소개 영역 약 200px 이내를 목표로 하며 실제 화면에서 확인한다.

## 시각 기준과 변경 범위

기존 흰색 배경 `#FFFFFF`, 본문 남색 `#182B43`, 링크 청색 `#255C94`, 경계선 `#DCE3EC`, 보조 배경 `#F5F7FB`를 재사용한다. 한글은 운영체제 기본 고딕을 사용한다. 왼쪽 정렬과 제목의 위계로 구분하며 큰 소개 박스·반복 버튼을 줄인다. 외부 글꼴이나 새 패키지는 추가하지 않는다.

현재 Odyssey 스킨 변환기와 CSS·JS 안에서 변경한다. 블로그 이름의 관리 설정도 같은 명칭으로 맞춘다. 글·주소·댓글·검색·코드 복사·접이식 목차·하루 한 편 발행·로그인 유지는 보존한다. 프로젝트 카드·경력 수치·다운로드 이력서·방문자 성과 표시는 추가하지 않는다.

## 적용 전후 확인

- 변경 전 스킨과 블로그 설정을 비공개 운영 디렉터리에 백업한다.
- 첫 글 제목의 시작 위치는 데스크톱 1440px 폭에서 위쪽 450px 이내, 모바일 390px 폭에서 480px 이내를 목표로 한다. 현재는 각각 약 553px와 543px이며 목표값은 아직 검증 전이다.
- 320·390·768·1440px에서 가로 넘침과 글 제목 잘림을 확인한다. 주요 조작 영역은 44px 이상, 키보드 포커스는 눈에 보이게 한다.
- 분류의 실제 글 수, 검색, GitHub 링크, 기존 글 두 편, 목차와 코드 복사를 실제 화면에서 확인한다.
- 스킨 변환의 재적용과 플랫폼 치환자 보존을 테스트하고, 하루 중복 발행 차단도 확인한다.

남은 결정: 제안한 명칭과 상세 배치를 포함한 본 설계의 적용 여부.
