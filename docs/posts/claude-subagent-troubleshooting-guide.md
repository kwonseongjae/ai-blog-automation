# Claude Code 서브에이전트가 안 불릴 때 점검하는 순서: 위치·머리글·이름·도구 설정을 하나씩 어겨 본 기록

같은 서브에이전트 파일을 열 가지 조건으로 바꾸고 조건마다 두 번씩 실행해 봤습니다. 등록되지 않았는데도 릴리스 노트가 맞게 나오는 경우가 있었습니다. 답변만 읽어서는 놓치기 쉬워서 등록 목록과 실제 호출 기록을 함께 확인했습니다.

확인일: 2026-11-16 · 범위: Linux 한 환경, Claude Code 2.1.325, 모델 별칭 haiku, 조건별 2회, 대화형 화면은 사용하지 않음

## 서브에이전트는 파일 하나와 머리글 두 줄로 만든다

문서에서 설명하는 서브에이전트는 특정 종류의 작업을 맡는 전문 도우미입니다. 자기만의 컨텍스트 창과 시스템 프롬프트를 가지며 도구 접근과 권한도 독립되어 있습니다. 파일은 YAML 머리글과 마크다운 본문으로 이루어집니다. 머리글에는 `name`과 `description`이 필수이고 본문에는 시스템 프롬프트를 씁니다.

현재 프로젝트의 파일 위치는 `.claude/agents/`이고 개인의 모든 프로젝트에서 쓸 위치는 `~/.claude/agents/`입니다. 우선순위는 조직 관리 설정, 현재 세션의 `--agents` 옵션, 프로젝트 위치, 개인 위치, 플러그인의 `agents/` 폴더 순입니다. 선택 항목인 `tools`를 생략하면 사용 가능한 모든 도구를 물려받습니다. `model`도 선택 항목입니다.

문서는 Claude가 `description`을 보고 위임 시점을 정하며 프롬프트에서 이름을 언급해도 위임 여부를 판단한다고 설명합니다. `@`로 고르면 해당 서브에이전트가 확실히 실행됩니다. `--agent <이름>`은 세션 전체의 메인 스레드에 그 서브에이전트의 도구 제한과 모델을 적용하는 옵션입니다.

## 정상 파일 하나를 열 가지 조건으로 바꿨다

기준 파일은 `.claude/agents/release-noter.md`에 두고 릴리스 노트를 만드는 지침을 넣었습니다. 답변 첫 줄에는 `[서브에이전트-7]`을 쓰도록 했습니다. 이 표시가 나오면 파일의 지침을 따랐는지 구분할 수 있을 것으로 봤습니다.

```markdown
---
name: release-noter
description: 변경 내용 목록을 릴리스 노트로 정리한다. 사용자가 변경 목록이나 커밋 목록을 주고 릴리스 노트를 요청할 때 사용한다.
tools: Read
---

변경 목록을 `- [분류] 내용` 줄로 정리하고 마지막 줄에 `총 N건`을 쓴다. 답변의 첫 줄에는 항상 `[서브에이전트-7]`을 적는다.
```

정상 파일에서 위치나 머리글을 바꿨고 도구 조건에서는 파일 쓰기를 요청했습니다. 조건마다 새 임시 폴더를 사용했습니다. 아래 표의 요청 구분은 이어지는 요청 문장과 같습니다.

| 조건 | 바꾼 내용 | 요청 |
|---|---|---|
| 정상 | 기준 파일 그대로 | 이름으로 맡기기, 이름 없이 요청하기 |
| 폴더 이름 오타 | `.claude/agent/`에 둠 | 이름으로 맡기기 |
| 다른 도구의 위치 | `.agents/agents/`에 둠 | 이름으로 맡기기 |
| description 없음 | `description` 줄 삭제 | 이름으로 맡기기, 이름 없이 요청하기 |
| name 없음 | `name` 줄 삭제 | 이름으로 맡기기 |
| 이름이 파일 이름과 다름 | 파일은 `release-noter.md`, `name`은 `notes-bot` | `release-noter`라는 이름으로 맡기기 |
| 머리글 닫힘 없음 | 머리글을 닫는 `---` 삭제 | 이름으로 맡기기 |
| 설명이 다른 용도 | `description`을 회의록 용도로 변경 | 이름 없이 요청하기 |
| 도구 Read만 | `tools: Read` 유지 | 파일 쓰기 시키기 |
| tools 생략 | `tools` 줄 삭제 | 파일 쓰기 시키기 |

이름으로 맡길 때는 다음 문장을 썼고 이름 없는 요청에서는 앞부분만 뺐습니다. `<변경 목록>` 자리에는 변경 내용을 넣었습니다.

```text
release-noter 서브에이전트로 릴리스 노트를 만들어 주세요. 변경: <변경 목록>
```

```text
릴리스 노트를 만들어 주세요. 변경: <변경 목록>
```

파일 쓰기 요청은 아래와 같으며 만들지 못하면 그 사실을 알려 달라고 덧붙였습니다. 대상 파일은 `notes.txt`입니다.

```text
release-noter 서브에이전트에게 notes.txt 파일을 만들어 "테스트" 한 줄을 쓰게 하세요. 못 하면 못 한다고 알려 주세요.
```

실행 명령에는 모델 별칭 `haiku`를 지정했고 출력은 `stream-json`으로 받았습니다. 대화형 화면은 사용하지 않았습니다.

```bash
claude -p "<요청>" --model haiku --setting-sources project,local --permission-mode acceptEdits --allowedTools Read Write Edit --output-format stream-json --verbose
```

확인은 두 갈래로 나눴고 시작 정보인 `init`의 `agents` 목록에서 등록 여부부터 봤습니다. 그다음 도구 호출 기록을 확인했습니다. `Agent` 도구의 `subagent_type`에 어떤 이름이 들어갔는지를 읽었습니다.

## 등록 여부는 시작 정보의 목록에서 확인한다

이번 실행의 기본 목록에는 `claude`, `Explore`, `general-purpose`, `Plan`, `statusline-setup`이 있었고 정상 파일의 이름은 여기에 추가됐습니다. 파일이 디스크에 있다는 사실과 등록 목록에 있다는 사실은 구분해서 봤습니다.

| 조건 | 시작 정보의 목록 | 이름으로 맡긴 결과 |
|---|---|---|
| 정상 | `release-noter` 있음 | 두 번 모두 `release-noter` 호출 |
| 폴더 이름 오타 | `release-noter` 없음 | 1회는 호출 없이 정의되지 않았다고 답함. 2회는 `general-purpose` 호출 |
| 다른 도구의 위치 | `release-noter` 없음 | 1회는 `release-noter` 호출 오류 뒤 파일을 찾았다고 답함. 2회는 `general-purpose` 호출 |
| description 없음 | `release-noter` 없음 | 1회는 직접 작성. 2회는 호출 오류 뒤 `general-purpose`에 같은 지침을 넘김 |
| name 없음 | `release-noter` 없음 | 두 번 모두 호출 오류 뒤 `general-purpose`에 지침을 넘김 |
| 이름이 파일 이름과 다름 | `notes-bot` 있음, `release-noter` 없음 | 1회는 바로 `notes-bot` 호출. 2회는 `release-noter` 호출 오류 뒤 `notes-bot` 호출 |
| 머리글 닫힘 없음 | `release-noter` 없음 | 1회는 `general-purpose` 호출. 2회는 호출 오류 뒤 직접 작성 |
| 설명이 다른 용도 | `release-noter` 있음 | 이름 없이 요청한 결과는 뒤 절에서 설명 |

등록되지 않은 이름을 호출하면 오류가 났고 사용할 수 있는 에이전트 목록도 함께 나왔습니다. 다른 도구의 위치에 파일을 둔 조건에서는 다음 오류를 받았습니다.

```text
Agent type 'release-noter' not found. Available agents: claude, Explore, general-purpose, Plan, statusline-setup
```

`name`을 지우면 목록에 올라오지 않았고 파일 이름이 대신 쓰이지도 않았습니다. `description`이 없거나 머리글을 닫지 않은 조건도 등록되지 않았습니다. 문서가 필수로 지정한 항목과 머리글 경계를 먼저 확인할 이유가 생겼습니다.

파일 이름과 `name`을 다르게 둔 조건에서는 `notes-bot`이 등록됐고 요청에 쓴 `release-noter`는 없었습니다. 목록의 이름은 머리글의 `name`을 따랐습니다. 답변에서도 `release-noter`가 없어 `notes-bot`에 맡겼다고 밝혔습니다.

## 등록되지 않아도 결과가 나오는 경우

가장 헷갈린 부분은 등록 실패 뒤에도 작업이 이어졌다는 점이며 결과만 읽으면 정상 호출처럼 보였습니다. 모델이 직접 릴리스 노트를 쓰기도 했습니다. `general-purpose` 서브에이전트에 파일의 지침을 넘겨 실행한 경우도 있었습니다.

다른 도구의 위치에 둔 조건과 머리글 닫힘이 없는 조건에서는 `general-purpose`가 호출됐고 답변 첫 줄에 `[서브에이전트-7]`이 나왔습니다. 처음에 넣어 둔 표시까지 맞았습니다. 하지만 시작 정보에는 `release-noter`가 없었습니다.

몇몇 답변은 등록되지 않아 다른 서브에이전트로 실행했다고 밝혔지만 그런 설명이 없는 경우도 있었습니다. 답변의 자연스러움이나 지정한 첫 줄만으로 등록을 판단할 수 없었습니다. 결과가 맞게 나왔다는 사실은 등록 확인이 아닙니다.

확인할 때는 시작 정보에 `release-noter`가 있는지 보고 실제 `Agent` 호출의 `subagent_type`도 읽습니다. `general-purpose`로 실행됐다면 요청한 이름의 서브에이전트가 호출된 것은 아닙니다. 오류 뒤에 작업이 계속됐는지도 호출 기록에서 확인할 수 있습니다.

## 이름으로 부르지 않으면 맡기지 않았다

정상 파일을 둔 상태에서 이름 없이 릴리스 노트를 요청했고 두 번 모두 메인 대화가 직접 작성했습니다. 서브에이전트 호출은 없었습니다. `description`을 회의록 용도로 바꾸거나 지운 조건에서도 같은 결과가 나왔습니다.

문서는 `description`을 보고 위임을 정한다고 설명하지만 이번에는 설명이 작업과 맞아도 자동 위임이 일어나지 않았습니다. 실행 조건은 `haiku`와 한 줄짜리 작업이었습니다. 이 결과만으로 `description`이 위임에 영향을 주지 않는다고 판단할 수는 없습니다.

이번 정상 조건에서는 이름을 명시한 요청이 두 번 모두 `release-noter` 호출로 이어졌고 이름 없는 요청은 그렇지 않았습니다. 호출을 확인하려는 단계에서는 요청에 이름을 넣는 편이 분명했습니다. 문서에 나온 `@` 선택 방법은 이번에 실행하지 않았습니다.

## 도구 제한은 지켜졌다

`tools: Read`인 서브에이전트에게 파일 쓰기를 시켰고 두 번 모두 `notes.txt`가 만들어지지 않았습니다. 답변은 읽기 도구만 있어서 파일을 만들 수 없다는 취지였습니다. 실행 명령의 허용 도구 목록에 `Write`와 `Edit`이 있어도 이 결과는 같았습니다.

`tools` 줄을 지운 조건에서는 두 번 모두 파일이 생겼고 내용은 `테스트` 한 줄이었습니다. 문서에 나온 도구 상속 설명과 같은 결과입니다. 등록과 호출이 확인된 뒤 작업을 못 한다면 서브에이전트의 `tools` 설정도 볼 필요가 있습니다.

## 서브에이전트가 안 불릴 때 확인하는 순서

1. 증상: 파일을 만들었는데 등록 목록에 이름이 없습니다. 원인 후보: 폴더 위치나 이름이 다릅니다. 확인: 현재 프로젝트의 `.claude/agents/`인지 확인하고 `.claude/agent/`와 `.agents/agents/`를 구분합니다.

2. 증상: 위치가 맞아도 이름이 목록에 없습니다. 원인 후보: 필수 머리글 항목이 빠졌거나 머리글이 닫히지 않았습니다. 확인: `name`과 `description`을 확인하고 머리글 앞뒤의 `---`도 확인합니다.

3. 증상: 요청한 이름은 없는데 다른 이름이 등록돼 있습니다. 원인 후보: 파일 이름과 머리글의 이름이 다릅니다. 확인: `name` 값을 시작 정보의 목록과 대조합니다. 이번 실행에서는 그 값이 등록 이름이었습니다.

4. 증상: 답변은 맞는데 원하는 서브에이전트가 실행됐는지 불분명합니다. 원인 후보: 메인 대화가 직접 작성했거나 `general-purpose`가 대신 실행했습니다. 확인: 시작 정보의 목록을 보고 `Agent` 호출의 `subagent_type`도 확인합니다.

5. 증상: 등록은 됐는데 일반적인 요청에서 호출되지 않습니다. 원인 후보: 해당 요청에서 자동 위임을 선택하지 않았습니다. 확인: `description`을 읽고 요청에 등록된 이름을 명시해 호출 기록을 비교합니다.

6. 증상: 파일을 추가해도 반영되지 않거나 호출된 뒤 파일을 쓰지 못합니다. 원인 후보: 폴더 감지 조건이나 도구 제한입니다. 확인: 세션 시작 뒤 첫 `agents` 폴더를 만들었는지 확인하고 `tools`에 필요한 도구가 있는지 봅니다. `--add-dir`로 추가한 폴더인지도 확인합니다.

## 이 실험으로 알 수 없는 것

문서는 파일을 추가하거나 고치면 몇 초 안에 감지하며 다음 위임부터 새 정의를 쓴다고 설명합니다. 세션 시작 때 없던 `agents` 폴더에 첫 파일을 만든 경우에는 재시작이 필요하다고 합니다. `--add-dir`로 추가한 폴더의 `.claude/agents/`는 감시하지 않는다는 설명도 있습니다. 이 동작들은 이번에 직접 확인하지 않았습니다.

현재 `/agents`는 프로젝트 위치와 개인 위치의 파일을 직접 고치거나 Claude에게 부탁하라고 안내하며 문서는 이전 동작도 구분합니다. v2.1.197 이하에서는 대화형 마법사가 열립니다. 이번에는 대화형 화면의 `/agents`를 실행하지 않았습니다.

`--agents`와 `--agent` 옵션은 시험하지 않았고 개인 위치에서의 등록도 확인하지 않았습니다. 다른 모델과 Windows·macOS에서의 동작도 범위 밖입니다. Codex 역시 비교하지 않았습니다.

조건별 두 번씩만 실행했으므로 각 결과가 나타날 빈도까지 판단할 수 없고 세 번 이상 반복한 결과도 없습니다. 다만 등록 실패 뒤에도 답변이 완성될 수 있다는 점은 확인했습니다. 같은 답변이 나왔다는 이유만으로 설정이 정상이라고 판단하면 등록 실패를 놓칠 수 있습니다.
