# AI 에이전트란? 챗봇과 다른 점과 처음 맡길 일 3가지

“이 문서를 요약해줘”에서 한발 더 나아가, 프로젝트 파일을 읽고 필요한 정보를 찾아오게 할 수 있을까요? AI 에이전트는 목표에 맞춰 도구를 사용하고, 확인한 결과를 바탕으로 다음 행동을 고르는 시스템입니다. 처음에는 README 한 장에서 정보를 찾는 일부터 맡겨보면 차이가 보입니다.

확인일: 2026-11-15 · 읽기 도구만 제공한 실제 실행을 기준으로 설명합니다.

## 챗봇·자동화·에이전트는 무엇이 다른가

화면에 채팅창이 있는지만으로 구분하기는 어렵습니다. 채팅 서비스도 파일 검색을 할 수 있습니다. 내가 다음 행동을 매번 정하는지, 코드에 순서가 고정돼 있는지, 시스템이 결과를 보고 고르는지에 주목하면 이해하기 쉽습니다.

| 구분 | 다음 행동을 정하는 방식 | 처음 써볼 예 |
| --- | --- | --- |
| 일반적인 채팅 | 사람이 질문을 이어감 | 붙여 넣은 문서 요약 |
| 정해진 자동화 | 코드에 정한 순서대로 진행 | 매일 같은 시간에 원고 발행 |
| 에이전트 | 목표와 허용된 도구 안에서 선택 | 프로젝트를 읽고 실행 방법 찾기 |

이 구분은 기능을 이해하기 위한 기준입니다. 하나의 제품 안에도 세 방식이 함께 들어갈 수 있습니다. 제 블로그의 예약 발행은 순서가 정해진 자동화이고, 파일을 살펴보며 원인을 찾는 작업에는 에이전트를 활용할 수 있습니다.

## 첫 작업은 이 세 가지 중 하나면 된다

처음부터 “내 컴퓨터를 알아서 관리해줘”라고 맡기면 바뀐 내용을 확인하기 어렵습니다. 답을 원문과 바로 비교할 수 있는 일을 고르는 편이 낫습니다.

| 맡길 일 | 요청에 적을 범위 | 내가 확인할 것 |
| --- | --- | --- |
| 문서에서 정보 찾기 | README 한 장만 읽기 | 원문에 있는 값인가 |
| 프로젝트 구조 이해 | 지정한 폴더를 변경 없이 설명 | 폴더 역할의 근거가 있는가 |
| 오류 조사 순서 잡기 | 민감한 내용을 지운 오류 메시지 | 원인 후보와 확인 방법을 구분했는가 |

이번에는 첫 번째를 골랐습니다. 파일을 읽는 도구 하나만 제공하고, 공개 저장소 README에서 세 값을 찾도록 했습니다.

## README 한 장으로 직접 확인했다

![요청 범위를 정하고 README를 읽은 뒤 반환값을 원문과 비교하는 순서](asset:flow)

Claude Code 2.1.322 실행에 보낸 요청입니다. 요청 문장뿐 아니라 제공하는 도구도 읽기로 제한했습니다.

```text
README.md 파일 하나만 읽어주세요.
새 기술블로그 주소, 독립 실습 파일 경로, Python 테스트 명령을 찾으세요.
다른 파일 읽기, 파일 수정, 명령 실행, 웹 접근은 하지 마세요.
blog_url, lab_path, test_command 세 필드의 JSON으로 답하세요.
없는 정보는 추측하지 말고 빈 문자열로 표시하세요.
```

실제 반환값은 다음과 같았습니다.

```json
{
  "blog_url": "https://jacks-aiblog.tistory.com/",
  "lab_path": "labs/learning_basics.py",
  "test_command": "python3 -m unittest discover -s tests -v"
}
```

세 값은 당시 README 내용과 일치했습니다. 관찰한 도구 호출도 Read였습니다. 다만 이번 실행은 읽기 도구 사용을 확인한 작은 사례입니다. 여러 단계의 자율 작업 성능이나 다른 프로젝트에서의 정확도를 측정한 결과는 아닙니다.

## 잘 답했는지는 이렇게 확인한다

파일 경로가 그럴듯하다고 넘어가면 잘못된 설명이 다음 작업으로 이어집니다. 저는 다음 순서로 답을 대조했습니다.

- 주소는 README의 새 블로그 링크와 비교했습니다.
- 실습 경로는 README의 파일 링크와 비교했습니다.
- 테스트 명령은 README의 명령 블록과 글자 단위로 비교했습니다.

원문에 없다면 “없다”는 답이 맞습니다. 답변을 채우기 위해 명령을 만들어내는 것보다 빠진 설명을 찾아주는 편이 프로젝트를 정리하는 데 도움이 됩니다.

## 내 프로젝트에는 어떻게 응용할까

블로그 자동화에서는 “오늘 왜 발행하지 않았는가”를 조사하는 데 적용할 수 있습니다. 우선 공개해도 되는 상태 예시와 발행 코드를 읽게 하고, 완료·진행 중·원고 없음 중 어디에 해당하는지 근거를 받는 식입니다. 이 응용은 다음에 진행할 과제이며, 이번 README 실습에서 실행한 내용은 아닙니다.

작업을 늘릴 때는 읽기, 수정, 실행을 한 번에 맡기기보다 결과 하나씩 확인하면 좋습니다. “수정하지 마세요”라는 문장과 실제 도구 권한은 별개이므로, 쓰는 제품에서 허용된 동작도 함께 확인합니다.
