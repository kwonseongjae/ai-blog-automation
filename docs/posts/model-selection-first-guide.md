# AI 코딩 모델 선택 기준: 같은 버그 수정을 여러 모델로 돌려 본 결과

AI 코딩 모델 선택 기준을 정하려고 같은 버그 수정을 여러 모델로 돌리고 걸린 시간과 표시된 사용량을 기록했습니다. 그 결과를 바탕으로 처음 모델과 추론 강도를 고를 때 쓸 기준을 정리합니다. 어느 모델이 가장 좋다는 결론을 내리는 글은 아닙니다.

확인일: 2026-11-15 · 범위: Linux 한 환경, Codex CLI 0.167.2, Claude Code 2.1.325, 조건별 1회 실행

## 모델과 추론 강도는 따로 고른다

모델은 어떤 모델에 작업을 맡길지 고르는 설정이고 추론 강도는 생각하는 데 얼마나 일을 쓸지 조절하는 설정입니다. 두 설정을 나눠 봐야 합니다. 같은 모델도 강도를 바꿔 실행할 수 있습니다.

Codex 모델 문서는 속도와 비용, 능력 사이의 균형을 설명하며 잘 아는 작업으로 결과를 비교하라고 안내합니다. 기다릴 수 있는 시간과 필요한 사용량도 판단 기준입니다. 작업이 바뀌면 모델을 바꿀 수 있습니다.

문서에서 Astra는 가장 까다로운 작업용으로 소개하고 GPT-6.1 Sol은 Astra에 가까운 성능을 더 낮은 비용으로 내는 모델로 설명합니다. Sol의 용도에는 반복적이고 오래 걸리는 작업이 포함됩니다. GPT-6.1 Terra는 글쓰기·시각 이해·컴퓨터 사용에 빠른 선택으로 소개합니다. Luna는 요약·추출·집중된 코딩 같은 대량 작업에 가장 효율적인 모델로 소개합니다.

Codex의 추론 강도는 요청을 생각하는 데 쓰는 일을 조절하며 높이면 시간이 더 걸리고 토큰을 더 쓸 수 있습니다. 복잡한 작업의 결과가 좋아질 수도 있습니다. 문서는 기본 강도로 시작하고 깊은 계획이나 분석이 필요할 때 올리라고 안내합니다.

CLI의 Light는 설정값 `low`에 해당하고 Medium은 속도와 깊이의 균형을 잡는 단계입니다. Low는 빠르고 범위가 분명한 작업에 맞습니다. High와 Extra High는 여러 단계나 자료, 절충이 있는 어려운 작업에 맞는다고 설명합니다. Max와 Ultra는 대부분의 작업에 필요하지 않다고 합니다.

강도 이름은 모델 세대 사이에 정확히 대응하지 않으므로 익숙한 작업을 낮은 설정으로 시험하며 조정하라는 안내도 있습니다. 이름만 보고 같은 조건이라고 생각하기는 어렵습니다.

대화형 Codex CLI에서는 `/model`로 모델과 추론 강도를 바꾸고 실행을 시작할 때는 `--model`이나 `-m`을 씁니다. 한 번 실행하는 명령에도 지정할 수 있습니다.

```bash
codex exec -m gpt-6.1-sol "..."
```

기본 모델은 `config.toml`의 `model` 항목으로 정하고 지정하지 않으면 추천 모델을 씁니다. GPT-6.1 Terra는 Codex CLI 0.159.0 이상이 필요합니다. 실행 명령은 `codex -m gpt-6.1-terra`입니다.

Claude Code 모델 설정 문서는 별칭으로 용도를 구분하며 별칭이 가리키는 권장 버전은 시간이 지나면 바뀐다고 설명합니다. 아래 버전은 Anthropic API 기준입니다.

| 별칭 | 가리키는 버전 | 문서에서 설명하는 용도 |
|---|---|---|
| `sonnet` | Sonnet 5.5 | 일상적인 코딩 |
| `opus` | Opus 5.5 | 복잡한 추론 |
| `haiku` | Haiku 5.5 | 단순한 작업을 빠르게 처리 |
| `fable` | Fable 5.2 | 가장 어렵고 오래 걸리는 작업 |
| `opusplan` | 계획 모드에서는 opus, 실행에서는 sonnet | 계획과 실행에 다른 모델 사용 |
| `best` | opus와 같음 | opus와 같은 별칭 |

제공 서비스에 따라 별칭이 더 이전 버전을 가리킬 수 있고 특정 버전에 고정하려면 전체 모델 이름을 씁니다. Fable은 어떤 요금제에서도 기본 모델이 아닙니다. 사용하려면 `/model fable`이나 `claude --model fable`로 직접 골라야 합니다.

Claude Code의 effort는 모델이 단계마다 생각할지와 얼마나 생각할지 정하는 적응형 추론을 조절합니다. 낮은 강도는 단순한 작업에서 빠르고 저렴한 쪽입니다. 높은 강도는 복잡한 문제에서 더 깊게 추론하는 쪽입니다.

단계는 `low`, `medium`, `high`, `xhigh`, `max`이고 지원 범위는 모델마다 다릅니다. Fable 5.2와 Opus 5.5, Sonnet 5.5와 Haiku 5.5의 기본값은 모두 `medium`입니다. `/effort`나 `/model` 선택 창에서 바꿀 수 있습니다. 시작할 때 `--effort`를 지정하는 방법도 있습니다.

모델 설정은 세션 중 `/model`이 가장 우선하고 그다음은 시작할 때 지정하는 `claude --model`입니다. 이후 순서는 `ANTHROPIC_MODEL`, 설정 파일의 `model`, 새 세션 기본값인 `ANTHROPIC_DEFAULT_MODEL`입니다. `/model`만 입력하면 선택 창이 열립니다. Enter는 기본값으로 저장하고 `s`는 이번 세션에만 적용합니다.

## 같은 버그 수정을 여러 모델로 돌렸다

과제는 앞선 글과 같은 작은 Python 폴더이며 수정 대상은 `textutil.py`의 `slugify(text)`입니다. 테스트는 3개입니다. 처음에는 2개가 실패했습니다.

각 실행에는 같은 시작 폴더를 새로 복사해 주고 아래 요청 문장을 그대로 사용했습니다. 테스트 파일 수정은 금지했습니다.

> tests 폴더의 테스트가 실패합니다. 원인을 찾아 textutil.py만 고치고 python3 -m unittest discover -s tests 로 통과를 확인해 주세요. 테스트 파일은 수정하지 마세요. 마지막에 무엇을 고쳤는지 두 줄로 알려주세요.

성공 기준은 테스트 3개 통과로 잡았고 테스트 파일의 해시도 비교했습니다. 실행 명령은 다음과 같습니다. `<요청 문장>`에는 위 문장을 넣었습니다.

```bash
codex exec -m <모델> -c model_reasoning_effort=<강도> -s workspace-write --skip-git-repo-check "<요청 문장>"

claude -p "<요청 문장>" --model <별칭> --permission-mode acceptEdits \
  --allowedTools "Read" "Edit" "Write" "Bash(python3 -m unittest *)" --output-format json \
  --setting-sources project,local
```

모든 조건에서 테스트 3개가 통과했고 테스트 파일의 해시도 같았습니다. 테스트 파일은 수정되지 않았습니다.

Codex는 추론 강도를 명시해 실행했고 사용량은 출력에 표시된 총 토큰 수를 기록했습니다. 결과는 다음과 같습니다.

| 모델 | 추론 강도 | 걸린 시간(초) | 표시된 사용량(토큰) | 고친 방식 |
|---|---|---:|---:|---|
| gpt-6.1-sol | low | 26.3 | 37,403 | 문자를 하나씩 걸러 남김 |
| gpt-6.1-sol | medium | 30.1 | 19,879 | 정규식으로 기호 제거 |
| gpt-6.1-terra | medium | 25.7 | 18,847 | 문자를 하나씩 걸러 남김 |
| gpt-6-luna | medium | 26.8 | 16,512 | 정규식으로 기호·공백을 하이픈으로 바꾸고 양끝 하이픈 제거 |

Claude Code는 `--effort`를 지정하지 않았고 아래 별칭의 문서상 기본값은 `medium`입니다. 버전 표기는 Anthropic API 기준입니다. 비용은 이번 실행에 표시된 값이며 가격표의 단가가 아닙니다.

| 별칭(버전) | 걸린 시간(초) | 턴 수 | 출력 토큰 | 표시된 비용(달러) | 고친 방식 |
|---|---:|---:|---:|---:|---|
| haiku(Haiku 5.5) | 12.5 | 6 | 1,645 | 약 0.004 | 정규식으로 기호 제거 |
| sonnet(Sonnet 5.5) | 7.9 | 5 | 859 | 약 0.058 | 정규식으로 기호 제거 |
| opus(Opus 5.5) | 17.2 | 4 | 1,019 | 약 0.116 | 정규식으로 글자·숫자 덩어리만 추출 |
| fable(Fable 5.2) | 13.8 | 3 | 670 | 약 0.223 | 정규식으로 글자·숫자 덩어리만 추출 |

두 도구는 사용량을 표시하는 방식이 다르고 위 표의 토큰 수도 같은 범위가 아닙니다. Claude Code는 입력 토큰을 캐시 생성과 캐시 읽기로 나눠 표시합니다. Codex는 총 토큰 한 숫자만 표시했습니다. 두 도구의 사용량 숫자는 직접 비교하지 않습니다.

이번에는 sol low가 37,403토큰을 썼고 sol medium은 19,879토큰을 썼습니다. 낮은 강도가 더 적은 토큰을 쓴 결과는 아니었습니다. 다만 조건별 한 번의 기록입니다. 다른 작업에서도 같다고 볼 근거는 없습니다.

앞선 글의 terra low는 71.3초가 걸렸고 이번 terra medium은 25.7초가 걸렸습니다. 당시에는 설정 파일의 기본값으로 실행했습니다. 토큰은 각각 18,882와 18,847로 거의 같았습니다. 시간은 한 번의 측정으로 믿기 어렵다는 점이 드러납니다.

Claude Code에서는 haiku가 6턴을 사용했고 걸린 시간도 가장 짧지는 않았습니다. 표시된 비용은 이번 실행에서 haiku, sonnet, opus, fable 순으로 커졌습니다. 이 순서는 실행에 표시된 비용의 순서입니다. 모델의 능력 순위나 사용 한도를 뜻하지 않습니다.

테스트에 없는 입력도 넣어 봤고 같은 테스트를 통과한 코드들이 서로 다른 결과를 냈습니다. 입력은 아래 네 개입니다.

| 입력 | opus·fable·luna 결과 | haiku·sonnet·sol medium 결과 | sol low·terra 결과 |
|---|---|---|---|
| `a_b` | `a-b` | `a_b` | `ab` |
| `a-b` | `a-b` | `a-b` | `a-b` |
| `a--b` | `a-b` | `a--b` | `a--b` |
| `--a--` | `a` | `--a--` | `--a--` |

이 입력들의 기대 동작은 요청에 정하지 않았으므로 어느 결과가 맞는지는 판단하지 않습니다. 모두 같은 테스트 3개를 통과한 코드입니다. 테스트 통과가 같은 동작을 보장하지는 않았습니다.

## 처음 고른다면

첫 선택은 도구의 기본값으로 시작하고 익숙한 작업 하나로 결과를 확인하는 쪽입니다. Codex 문서는 기본 추론 강도로 시작하라고 안내합니다. Claude Code도 앞서 소개한 버전의 기본 강도가 `medium`으로 정해져 있습니다.

모델을 바꿔 볼 때는 잘 아는 작업을 쓰고 결과와 걸린 시간, 표시된 사용량을 함께 기록합니다. Codex 문서가 제시하는 비교 방법입니다. 이번 slugify 실행도 그 예입니다.

추론 강도는 작업에 맞춰 조정하되 낮은 설정이 항상 사용량도 적을 것이라고 가정하지 않습니다. 이번 sol 실행에서는 그렇지 않았습니다. 깊은 계획이나 분석이 필요한 작업이라면 강도를 올려 비교할 근거가 생깁니다.

원하는 동작이 있다면 요청 문장에 적고 확인할 수 있는 테스트도 둡니다. 이번에는 밑줄을 어떻게 처리할지 정하지 않았습니다. 그 빈자리가 서로 다른 코드로 남았습니다.

모델 이름은 확인일과 함께 보고 별칭을 쓴다면 가리키는 버전도 확인합니다. Claude Code의 별칭은 시간이 지나며 바뀝니다. Codex도 모델이 종료됩니다. 문서에는 GPT-5.5 종료와 GPT-6.1 Sol 등으로의 교체 안내가 예로 나옵니다.

## 가격과 한도는 글에 적지 않았다

가격과 사용 한도는 자주 바뀌고 계정에서 쓸 수 있는 모델도 달라집니다. 이번에는 가격표와 사용 한도를 확인하지 않았습니다. 본문에 적은 달러 금액은 실행 결과에 표시된 비용입니다. 모델 단가나 요금제 가격으로 읽으면 안 됩니다.

Codex 모델 문서는 가용성과 가격, 사용 한도를 별도 도움말에서 확인하도록 안내합니다. Claude Code 모델 설정 문서도 비용을 다루는 별도 페이지로 연결합니다. 실제 선택 전에는 아래 공식 문서에서 해당 안내를 따라 확인할 수 있습니다.

## 이 실험으로 알 수 없는 것

각 조건은 한 번만 실행했고 다시 돌리면 시간과 사용량, 고치는 방식이 달라질 수 있습니다. 반복 측정한 평균이 아닙니다. 이번 숫자로 평소 성능을 단정할 수 없습니다.

과제가 작고 쉬워 모든 모델이 통과했으며 모델 간 능력 차이는 드러나지 않았습니다. 어려운 작업이나 큰 프로젝트에서의 차이는 모릅니다. 여러 파일을 수정하는 작업도 확인하지 않았습니다.

두 도구의 모델 결과를 나란히 제시했지만 모델 수준과 추론 설정이 같은 조건은 아닙니다. 사용량 집계와 개인 설정 범위도 다릅니다. Codex는 개인 전역 설정을 끄지 않았습니다. Claude Code는 `--setting-sources project,local`로 개인 설정을 제외했습니다.

요금제와 계정에 따라 모델 가용성이 달라지므로 이 환경에서 쓸 수 있었던 모델만 실행했습니다. Astra는 실행하지 않았습니다. 가격표와 사용 한도도 미확인 상태입니다. 이 기록은 각 도구에서 처음 비교할 작업을 정하는 예로만 읽습니다.
