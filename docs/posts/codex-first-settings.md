# Codex 설치 방법: 처음 쓸 때 로그인·작업 폴더까지 확인하는 법

Codex CLI는 터미널에서 프로젝트 파일을 읽고, 코드를 바꾸거나 명령을 실행하도록 요청하는 도구입니다. 처음에는 설치 명령만 따라가기보다 작업 폴더와 권한을 확인하고, 변경 없는 설명 작업부터 시작해보면 좋습니다.

확인일: 2026-11-15 · 범위: Codex CLI · 로컬 확인 버전: 0.167.2

## 어떤 Codex를 쓰는 글인가

Codex는 터미널에서 사용하는 CLI 외에도 코드 편집기 확장과 클라우드 작업 등 여러 환경에서 사용할 수 있습니다. 같은 이름을 쓰더라도 작업하는 위치와 화면은 다릅니다. 이 글은 직접 선택한 폴더에서 실행하는 CLI를 기준으로 합니다.

터미널이 낯설다면 한 줄씩 명령을 입력하는 창이라고 생각하면 됩니다. Windows의 PowerShell과 WSL의 Linux 터미널은 서로 다른 환경이므로, 설치 명령을 실행하기 전에 현재 어느 창에 있는지부터 확인합니다. 기본 PowerShell 프롬프트는 `PS C:\Users\사용자>`처럼 시작하고, WSL의 Linux 셸은 `user@PC:~$`와 같은 형태를 볼 수 있습니다. 표시 모양은 바꿀 수 있으므로 Windows Terminal의 현재 탭이 PowerShell인지 Ubuntu 같은 WSL 배포판인지도 확인합니다.

## 설치할 창부터 고른다

| 지금 사용하는 창 | 설치 안내 | 확인할 위치 |
| --- | --- | --- |
| Windows PowerShell | Windows용 설치 프로그램 | Windows의 프로젝트 폴더 |
| WSL Ubuntu 등 | Linux용 설치 프로그램 | WSL 안의 프로젝트 폴더 |
| npm이 이미 있는 환경 | 공식 npm 패키지 | 해당 환경의 PATH |

## 설치는 현재 공식 안내에서 한 방법을 고른다

[공식 CLI 문서](https://learn.chatgpt.com/docs/codex/cli.md)에는 운영체제별 설치 방법이 있습니다. Windows의 새 PowerShell 창에서는 다음 설치 명령을 안내합니다.

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

macOS·Linux에서는 다음 방법을 안내합니다. WSL을 사용 중이라면 WSL 터미널 안에서 Linux용 안내를 따릅니다.

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

이 명령들은 공식 주소의 설치 프로그램을 내려받아 실행합니다. 주소를 임의의 블로그 단축 링크로 바꾸지 말고, 설치하려는 환경에서 공식 안내와 같은지 확인한 뒤 실행합니다. 이미 npm을 사용하는 환경에서는 공식 저장소가 안내하는 다음 방법도 있습니다. 여러 설치 방법을 동시에 적용할 필요는 없습니다.

```bash
npm install -g @openai/codex
```

이 글에서는 기존 WSL 환경의 버전과 도움말을 확인했습니다. 새 Windows 계정에서 설치부터 로그인까지 다시 수행한 기록은 아닙니다. 설치가 끝나면 새 터미널에서 버전부터 확인합니다.

```bash
codex --version
codex --help
```

## 첫 로그인에서 비용 경로를 확인한다

작업할 프로젝트 폴더에서 `codex`를 실행합니다. 처음 실행하면 공식 안내에 따라 ChatGPT 계정 로그인 등 사용할 인증 방식을 고릅니다.

```bash
cd my-project
codex
```

`my-project`는 예시 이름입니다. 실제로 사용할 폴더로 바꿉니다. 계정의 이용 가능 범위와 한도는 현재 요금제·조직 설정에 따라 확인해야 합니다. ChatGPT 계정 로그인과 별도 API 키 사용을 같은 결제 방식으로 생각하면 혼동하기 쉽습니다. API 키가 필요한 방식인지 먼저 구분하면 불필요한 키 발급을 줄일 수 있습니다. [공식 저장소](https://github.com/openai/codex)의 로그인 안내에서 현재 지원 범위를 확인할 수 있습니다.

## 첫 요청은 설명만 받는다

처음 연 폴더에 업무 자료나 인증 파일을 전부 넣기보다 공개해도 되는 작은 예제 프로젝트로 시작합니다. 다음 요청은 복사해서 쓸 수 있는 예시입니다.

```text
이 프로젝트의 README를 읽고 아래 항목을 정리해주세요.
- 무엇을 하는 프로젝트인지
- 실행하려면 무엇이 필요한지
- README에서 확인한 실행 명령
파일을 수정하거나 명령을 실행하지 마세요.
확인한 내용과 추측을 구분하고, 근거 파일을 적어주세요.
```

답변이 그럴듯한지보다 README에 실제로 적힌 내용인지 확인합니다. 설명을 받은 뒤 한 파일의 작은 수정처럼 다음 작업을 좁혀가면 변경을 이해하기 쉽습니다. 위 예시는 요청 문장이며, 이 글에서 해당 요청의 응답 결과를 측정한 것은 아닙니다.

## 권한은 요청 문장과 별도로 확인한다

CLI의 `/permissions`에서 현재 실행 환경이 허용하는 범위를 살펴봅니다. 샌드박스는 접근할 수 있는 자원을, 승인은 어떤 행동을 실행하기 전에 검토할지를 정하는 서로 다른 제어입니다. 관리 환경에서는 선택 가능한 항목이 다를 수 있습니다. [공식 권한 안내](https://learn.chatgpt.com/docs/permission-modes.md)에서 현재 명칭과 조건을 확인합니다.

로컬 0.167.2 도움말에서는 다음과 같이 일회성 실행 범위를 지정하는 옵션도 확인할 수 있었습니다.

```bash
codex --sandbox read-only --ask-for-approval on-request
```

이 예시는 변경 없는 탐색을 시작할 때 검토할 설정입니다. `read-only`는 쓰기를 제한하는 설정이지, 파일을 읽는 작업까지 모두 금지하는 설정은 아닙니다. 읽어서는 안 되는 자료를 작업 폴더에 넣지 않았는지도 별도로 확인합니다. 조직 정책에 의해 옵션이 제한될 수도 있습니다.

## 명령을 못 찾거나 답변이 이상할 때

| 증상 | 먼저 확인할 것 |
| --- | --- |
| 설치했는데 명령을 못 찾음 | 새 터미널을 열었는지, 설치한 환경이 같은지 |
| 엉뚱한 프로젝트를 설명함 | 현재 작업 폴더가 맞는지 |
| 답변에 실행 명령이 없음 | README에 해당 명령이 실제로 있는지 |
| 실행했다는데 결과가 없음 | 제안한 명령과 실제 실행 결과를 구분했는지 |

## 다음 작업을 맡기기 전 확인할 것

첫 실행이 되면 곧바로 프로젝트 전체를 고치게 하기보다, 설명의 근거가 맞는지부터 봅니다. 수정 작업으로 넘어갈 때는 Git 변경 내역을 남기고, 바꿀 파일과 확인할 결과를 요청에 적습니다. “실행할 명령을 제안했다”와 “명령을 실행해 통과했다”도 구분합니다.

현재 로컬에서 확인한 것은 버전 출력과 옵션 존재 여부입니다. 운영체제별 새 설치 화면과 계정별 이용 한도는 자신의 환경에서 확인해야 합니다.
