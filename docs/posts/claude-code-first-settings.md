# Claude Code 설치 방법: Windows와 WSL 명령을 섞지 않는 법

Claude Code를 처음 설치할 때는 Windows PowerShell인지 WSL 터미널인지 먼저 확인해야 합니다. 설치 위치를 정하고 로그인 방식과 권한을 확인한 뒤, README 한 장을 읽는 작업으로 첫 사용을 시작해봅시다.

확인일: 2026-11-15 · 범위: Claude Code CLI · 로컬 확인 버전: 2.1.322

## 웹 채팅과 CLI는 시작하는 곳이 다르다

브라우저에서 Claude와 대화하는 것과, 프로젝트 폴더에서 Claude Code를 실행하는 것은 작업 환경이 다릅니다. CLI는 선택한 폴더의 파일을 읽고 도구를 사용할 수 있어, 파일과 명령을 다루는 요청에 쓰기 좋습니다.

이 글에서는 작은 코드 프로젝트를 이해하는 첫 작업을 다룹니다. 터미널이 처음이라면 설치할 창을 여는 방법부터 [공식 터미널 안내](https://code.claude.com/docs/en/terminal-guide)를 확인해도 좋습니다. 도구를 쓰기 위해 처음부터 큰 프로젝트를 만들 필요는 없습니다.

## PowerShell과 WSL 중 설치할 곳을 정한다

| 환경 | 입력할 명령의 형태 | 설치 뒤 실행할 곳 |
| --- | --- | --- |
| Windows PowerShell | `irm …install.ps1` | PowerShell |
| WSL Linux | `curl …install.sh` | 설치한 WSL 터미널 |

아래 명령은 환경별 선택지입니다. 표의 줄을 모두 실행할 필요는 없습니다.

![설치할 환경과 로그인 방식을 확인한 뒤 읽기 작업으로 시작하는 순서](asset:flow)

[공식 시작 안내](https://code.claude.com/docs/en/quickstart)의 Windows PowerShell 설치 명령은 다음과 같습니다.

```powershell
irm https://claude.ai/install.ps1 | iex
```

macOS·Linux·WSL의 터미널에서는 다음 명령을 안내합니다.

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

기본 PowerShell 창은 `PS C:\Users\사용자>` 같은 프롬프트를, WSL의 Linux 셸은 `user@PC:~$` 같은 형태를 볼 수 있습니다. 프롬프트는 바꿀 수 있으므로 현재 터미널 탭의 환경도 확인합니다.

두 방법은 같은 창에 차례로 입력하는 목록이 아닙니다. 설치할 환경 하나를 정해 해당 명령을 사용합니다. WSL을 선택했다면 WSL 안에서 설치하고 그 터미널에서 실행합니다. 프로젝트가 어느 환경에 있는지와 설치한 위치를 맞추면 “분명 설치했는데 명령을 찾지 못한다”는 상황을 줄일 수 있습니다.

이 명령들도 공식 주소의 프로그램을 내려받아 실행합니다. 공식 안내와 주소가 같은지 확인하고 실행합니다. 로컬에는 이미 설치된 WSL 환경이 있어, 이번 글을 준비하며 새 Windows 설치를 다시 수행하지는 않았습니다.

## 설치 뒤에는 새 터미널에서 확인한다

공식 안내는 설치가 끝난 뒤 새 터미널을 열어 버전을 확인하도록 설명합니다.

```bash
claude --version
```

로컬 확인에서는 `2.1.322 (Claude Code)`가 출력됐습니다. 이 숫자가 모든 독자의 최신 버전이라는 뜻은 아닙니다. 버전 출력 없이 명령을 못 찾는다면 설치를 반복하기 전에 터미널을 새로 열었는지와 공식 PATH 문제 해결 안내를 확인합니다.

## 로그인은 구독과 Console 사용을 구분한다

작업할 폴더에서 다음과 같이 시작합니다.

```bash
cd my-project
claude
```

처음 사용하면 안내에 따라 로그인합니다. 공식 문서는 지원되는 Claude 구독, Claude Console 등 인증 경로를 구분합니다. 브라우저에서 무료 채팅을 쓸 수 있다는 사실만으로 CLI의 이용 가능 범위까지 같다고 판단하지 않습니다.

구독으로 사용하는지 Console의 API 비용으로 사용하는지 구분하고 싶다면 세션에서 `/status`를 확인합니다. 이미 환경에 API 키가 있다면 로그인 과정이 달라질 수 있으므로, 사용하려는 계정과 비용 경로를 먼저 확인하는 편이 좋습니다. 구체적인 가격은 변경될 수 있어 이 글에 고정 금액을 적지 않았습니다.

## 첫 요청은 파일을 바꾸지 않는 설명으로

첫 작업 예시는 다음처럼 작게 잡습니다. 아래 문장은 사용 예시이며, 모든 프로젝트에서 같은 답이 나온다는 뜻은 아닙니다.

```text
README.md만 읽고 처음 실행할 때 알아야 할 내용을 정리해주세요.
설치해야 할 것, 실행 명령, 아직 설명이 없는 항목으로 나눠주세요.
파일을 수정하거나 명령을 실행하지 마세요.
README에 없는 내용은 추측으로 채우지 마세요.
```

위 예시 문장 자체의 응답을 이번에 측정한 것은 아닙니다. 앞선 에이전트 입문 글에서 다룬 별도 실습은 읽기 도구만 제공한 다른 실행입니다. 그 실습에서는 공개 저장소 README에서 블로그 주소·실습 파일·테스트 명령을 실제로 추출하고 원문과 대조했습니다. 이 첫 요청도 답변만 믿기보다 파일에 근거가 있는지 확인하는 방식으로 활용하면 됩니다.

## 첫 사용에서 헷갈리는 세 가지

| 헷갈리는 부분 | 구분할 기준 |
| --- | --- |
| 웹 채팅과 CLI | CLI는 선택한 프로젝트 폴더에서 시작 |
| 구독과 Console | 로그인한 계정과 비용 경로를 상태에서 확인 |
| 요청 문장과 권한 | 문장은 의도, 권한은 도구가 할 수 있는 동작 |

## 프롬프트와 권한 설정의 역할

“수정하지 마세요”라는 문장은 작업 범위를 설명하지만 권한 규칙을 대신하지 않습니다. `/permissions`에서 현재 모드와 허용 규칙을 확인합니다. [공식 문서](https://code.claude.com/docs/en/permissions)는 읽기·수정·명령 실행에 어떤 승인 규칙이 적용되는지 설명합니다.

처음부터 승인 절차를 모두 건너뛰는 설정을 복사하기보다, 변경 없는 설명 작업을 마친 뒤 작은 수정으로 넘어가는 편이 결과를 이해하기 쉽습니다. 설정 화면과 기본 모드는 버전·계정·조직 설정에 따라 다를 수 있으므로, 특정 화면이 반드시 나온다고 가정하지 않습니다.

익숙해진 뒤에는 프로젝트 설명과 실행 명령 같은 공통 맥락을 `CLAUDE.md`에 정리할 수 있습니다. 다만 이 파일도 접근 제어 장치는 아닙니다. 첫날에는 지침 파일이나 확장 기능을 늘리기보다, 작은 작업의 근거와 결과를 확인하는 데 집중해도 충분합니다.
