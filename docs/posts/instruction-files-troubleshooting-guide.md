# CLAUDE.md·AGENTS.md 지침 파일이 적용 안 될 때 점검하는 순서: 이름·위치·크기·요청을 하나씩 바꿔 표식 한 줄로 확인한 기록

CLAUDE.md나 AGENTS.md 같은 지침 파일이 적용됐는지 표식 한 줄로 확인하고 이름·위치·크기·요청을 하나씩 바꿔 봤습니다. 같은 “규칙을 안 따른다”는 증상이어도 표식이 사라지는 조건은 달랐습니다. 파일을 고치기 전에 어느 조건에서 달라지는지 좁히는 데 초점을 맞췄습니다.

확인일: 2026-11-16 · 범위: Linux 한 환경, Codex CLI 0.167.2, Claude Code 2.1.325, 조건별 1회 실행, 대화형 화면의 확인 명령은 쓰지 않음

## 지침이 읽히는 규칙은 도구마다 다르다

Codex 문서에서는 시작할 때 지침 목록을 만든다고 설명합니다. 전역 지침은 기본 `~/.codex`에서 찾으며 `CODEX_HOME`으로 위치를 바꿀 수 있습니다. `AGENTS.override.md`, `AGENTS.md` 순서로 확인해 비어 있지 않은 첫 파일만 씁니다.

프로젝트 지침은 프로젝트 루트에서 현재 작업 폴더까지 내려오며 찾고 루트는 보통 Git 루트입니다. 각 폴더에서는 `AGENTS.override.md`, `AGENTS.md`, `project_doc_fallback_filenames`에 적은 이름 순서로 확인합니다. 폴더마다 최대 한 파일을 씁니다. 프로젝트 루트를 찾지 못하면 현재 폴더만 확인합니다.

찾은 파일은 루트부터 빈 줄로 이어 붙이며 현재 폴더에 가까운 파일이 뒤에 와서 앞의 안내보다 우선합니다. 빈 파일은 건너뜁니다. 합친 크기가 `project_doc_max_bytes`의 기본값인 32 KiB에 닿으면 파일 추가를 멈춥니다.

Claude Code 문서에서는 작업 폴더와 그 위쪽 모든 폴더의 `CLAUDE.md`, `CLAUDE.local.md`를 시작할 때 읽는다고 설명합니다. 하위 폴더의 지침은 그 폴더의 다른 파일을 읽거나 쓰거나 고칠 때 불러옵니다. 시작할 때 전부 읽는 방식은 아닙니다.

`AGENTS.md`도 프로젝트 지침으로 읽을 수 있으며 `CLAUDE.md`에 `@AGENTS.md`를 적어 가져오는 방법도 있습니다. `@경로`로 파일을 가져오는 깊이는 최대 네 단계입니다. 파일당 200줄 이하를 권장합니다. 더 길면 컨텍스트를 더 쓰고 지침을 지키는 정도가 떨어진다고 설명하며 4 MiB를 넘는 파일은 읽지 않습니다.

확인 수단도 다릅니다. Codex 문서는 `codex status`와 지침 요약 요청을 안내하고 Claude Code 문서는 `/context all`과 `/memory`를 안내합니다. Claude Code의 하위 지침은 불러올 때 터미널에 `Loaded` 줄이 나옵니다. 여러 파일의 지침이 충돌하면 임의로 하나를 고를 수 있다는 설명도 있습니다.

## 표식 한 줄로 읽혔는지 확인한다

각 지침 파일에 아래 규칙을 적고 계산 질문을 보냈습니다. 답변 마지막 줄을 판정 기준으로 삼았습니다.

```text
모든 답변의 마지막 줄에 정확히 `[점검-7]`만 적는다.
```

기본 요청은 “2 더하기 3은 얼마인가요?”입니다. 마지막 줄에 `[점검-7]`이 있으면 지침을 읽고 따른 것으로 판정했습니다. 표식이 없으면 파일을 읽지 않았거나 읽었어도 따르지 않은 경우여서 이 방법만으로 둘을 구분하지 못합니다.

![지침 파일에 표식 규칙을 적고 조건을 하나씩 바꿔 답변 마지막 줄의 표식을 확인하는 순서](asset:flow)

조건마다 새 임시 폴더를 만들고 아래처럼 바꿨습니다. 두 파일이 충돌하는 조건에서는 표식도 서로 다르게 적었습니다.

| 조건 | 바꾼 내용 |
|---|---|
| 정상 | 작업 폴더에 `AGENTS.md` 또는 `CLAUDE.md`를 둠 |
| 요청이 충돌 | 정상 파일을 두고 요청 끝에 “숫자만 답하세요”를 붙임 |
| 소문자 이름 | 파일 이름을 `agents.md`, `claude.md`로 바꿈 |
| 하위 폴더에 파일 | 지침을 `sub/`에 두고 상위에서 실행. 계산 질문과 `sub/README.txt` 첫 줄을 묻는 요청을 사용 |
| 상위 폴더에 파일, git 없음 | 지침을 상위에 두고 `sub/`에서 실행 |
| 상위 폴더에 파일, git 있음 | 위 배치에서 상위 폴더에 `git init` 실행 |
| 파일 두 개 충돌 | Git 저장소의 상위 파일은 `[부모-1]`, `sub/` 파일은 `[자식-2]`를 요구. `sub/`에서 실행 |
| 큰 파일 | 62,886바이트, 703줄인 파일의 맨 끝에 규칙을 둠 |
| 큰 파일, 규칙 맨 앞 | 같은 크기의 파일에서 규칙을 맨 앞으로 옮김 |
| 덮어쓰기 파일 | Codex에서 `AGENTS.md`와 `[덮어쓰기-9]`를 요구하는 `AGENTS.override.md`를 함께 둠 |

Codex는 개인 설정이 섞이지 않도록 `CODEX_HOME`을 임시 폴더로 바꾸고 인증 파일만 링크했습니다. 실행 명령은 다음과 같습니다.

```bash
codex exec --json -m gpt-6.1-sol -c model_reasoning_effort=low -s read-only
```

Claude Code는 아래 명령으로 실행했으며 두 도구에 사용한 모델은 다릅니다. 결과는 도구 사이의 우열을 비교하는 자료로 쓰지 않습니다.

```bash
claude -p --model haiku --setting-sources project,local --allowedTools Read
```

## Codex는 이름·git 저장소·크기에서 갈렸다

정상 조건에서는 표식이 나왔고 파일 이름이나 배치를 바꾸자 결과가 달라졌습니다. 같은 파일에서도 요청 문구가 영향을 줬습니다.

| 조건 | 답변 마지막 줄 또는 관찰 결과 |
|---|---|
| 정상 | `[점검-7]` |
| 요청이 충돌 | `5`, 표식 없음 |
| 소문자 이름 `agents.md` | 표식 없음 |
| 하위 폴더에 파일, 상위에서 계산 요청 | 표식 없음 |
| 하위 폴더에 파일, `sub/README.txt` 첫 줄 요청 | `head -n 1 sub/README.txt` 실행 후에도 표식 없음 |
| 상위 폴더에 파일, git 없음 | 표식 없음 |
| 상위 폴더에 파일, git 있음 | `[점검-7]` |
| 파일 두 개 충돌 | `[자식-2]`만 나옴 |
| 큰 파일, 규칙 맨 끝 | 표식 없음 |
| 큰 파일, 규칙 맨 앞 | `[점검-7]` |
| 덮어쓰기 파일 | `[덮어쓰기-9]` |

처음에는 모든 요청에 “숫자만 답하세요”를 붙였고 표식이 나오지 않아 원인을 찾았습니다. 이 문구를 빼자 정상 조건에서 표식이 나왔습니다. 파일만 살피면 놓칠 수 있는 차이였습니다.

별도로 “현재 적용된 지침 파일의 내용을 요약해 주세요.”라고 요청하자 `AGENTS.md`의 규칙을 그대로 말했습니다. 이 결과는 파일은 읽혔지만 계산 요청의 지시를 더 우선한 것으로 보입니다. 다만 지시 우선순위를 확정하는 근거로 삼지는 않습니다.

상위 폴더의 지침은 Git 저장소가 있을 때만 적용됐으며 프로젝트 루트를 못 찾으면 현재 폴더만 확인한다는 문서 설명과 맞습니다. 두 파일이 충돌했을 때는 현재 폴더의 표식만 나왔습니다. 같은 폴더에 덮어쓰기 파일을 두면 그 파일의 표식이 나왔습니다.

큰 파일에서는 끝의 규칙을 따르지 않았고 같은 크기에서 규칙을 앞으로 옮기면 따랐습니다. 이 차이는 문서의 32 KiB 안내와 맞는 결과입니다. 파일 크기와 함께 규칙이 놓인 위치도 점검할 이유가 생겼습니다.

## Claude Code는 이름과 위치에서 갈렸다

Claude Code에서도 정상 이름의 파일은 적용됐고 소문자로 바꾼 파일에서는 표식이 사라졌습니다. 상위 폴더의 지침은 Git 저장소 유무와 관계없이 따랐습니다.

| 조건 | 답변 마지막 줄 또는 관찰 결과 |
|---|---|
| 정상 | `[점검-7]` |
| 요청이 충돌 | `[점검-7]` |
| 소문자 이름 `claude.md` | 표식 없음 |
| 하위 폴더에 파일, 상위에서 계산 요청 | 표식 없음 |
| 하위 폴더에 파일, `sub/README.txt` 첫 줄 요청 | `Read`로 파일을 읽은 뒤 `[점검-7]` |
| 상위 폴더에 파일, git 없음 | `[점검-7]` |
| 상위 폴더에 파일, git 있음 | `[점검-7]` |
| 파일 두 개 충돌 | `[자식-2]`만 나옴 |
| 큰 파일, 규칙 맨 끝 | `[점검-7]` |
| 큰 파일, 규칙 맨 앞 | `[점검-7]` |

하위 폴더에 지침을 두면 계산 질문에서는 표식이 없었고 그 폴더의 파일을 읽는 요청에서는 표식이 나왔습니다. 해당 폴더의 파일을 다룰 때 지침을 불러온다는 문서 설명과 같은 결과입니다.

두 파일이 충돌한 조건에서는 하위 폴더의 표식만 나왔지만 이를 고정된 우선순위로 해석하지 않습니다. 문서는 충돌 시 임의로 고를 수 있다고 설명합니다. 이번 결과는 그 조건에서 관찰한 응답으로 남깁니다.

703줄 파일도 규칙 위치와 관계없이 따랐으며 200줄 권장만 보고 예상한 것과는 차이가 있었습니다. 다만 시험한 지침은 단순한 규칙 한 줄입니다. 긴 파일의 여러 지침을 얼마나 지키는지는 확인한 결과가 없습니다.

## 같은 증상이어도 원인이 다르다

표식이 없다는 결과를 모아 보면 이름 문제와 탐색 범위 문제가 함께 섞여 있습니다. 요청 충돌도 같은 모습으로 나타났습니다.

| 표식이 없던 조건 | 해당 도구 | 원인 후보와 구분할 근거 |
|---|---|---|
| 소문자 이름 | 두 도구 | 이름 문제. 정식 이름의 정상 조건에서는 표식이 나옴 |
| 하위 폴더에 지침을 두고 상위에서 계산 요청 | 두 도구 | 위치와 불러오는 시점 문제. Claude Code는 해당 폴더의 파일을 읽는 요청에서 표식이 나옴 |
| 하위 폴더의 파일을 읽는 요청 | Codex | 하위 폴더 지침의 적용 범위 문제. 파일 내용을 확인한 뒤에도 표식이 없음 |
| Git 저장소 없이 상위 폴더에 지침 배치 | Codex | 프로젝트 루트 탐색 문제. 같은 배치에 Git 저장소를 만들면 표식이 나옴 |
| 큰 파일 끝에 규칙 배치 | Codex | 크기 한도에 걸렸을 가능성. 규칙을 앞으로 옮기면 표식이 나옴 |
| “숫자만 답하세요” 추가 | Codex | 요청과 지침의 충돌 가능성. 지침 요약 요청에서는 규칙 내용을 말함 |

두 파일의 충돌과 덮어쓰기 파일은 기본 표식 대신 다른 표식이 나온 경우라 별도로 봤습니다. 기대한 문자열이 없다는 이유만으로 지침 전체가 무시됐다고 판단하면 이 차이를 놓칩니다.

## 지침이 안 먹힐 때 확인하는 순서

1. 증상: 기본 표식부터 나오지 않습니다. 원인 후보: 파일 이름이 다르거나 내용이 비어 있습니다. 확인: 작업 폴더에 내용이 있는 `AGENTS.md` 또는 `CLAUDE.md`를 두고 기본 계산 질문으로 확인합니다.

2. 증상: 파일을 옮긴 뒤 적용되지 않습니다. 원인 후보: 실행 위치가 지침의 탐색 범위에서 벗어났습니다. 확인: 현재 작업 폴더와 파일 위치를 대조하고 Codex에서는 Git 루트 여부도 확인합니다. 문서가 안내하는 `codex status`로 기대한 작업 영역 루트인지 볼 수 있습니다.

3. 증상: 하위 폴더의 지침만 적용되지 않습니다. 원인 후보: 아직 불러오는 조건에 닿지 않았습니다. 확인: Claude Code에서는 그 폴더의 파일을 읽는 요청으로 바꿔 봅니다. 시작 시점의 목록과 나중에 불러온 지침을 구분합니다.

4. 증상: 파일 앞부분의 규칙은 따르는데 끝의 규칙은 빠집니다. 원인 후보: 크기 한도에 걸렸습니다. 확인: 같은 규칙을 파일 앞으로 옮겨 비교합니다. Codex 문서는 `project_doc_max_bytes`를 올리거나 큰 파일을 하위 폴더로 나누는 방법을 안내합니다.

5. 증상: 기대한 표식 대신 다른 안내를 따릅니다. 원인 후보: 다른 지침 파일이 적용되거나 내용이 충돌합니다. 확인: Codex에서는 홈과 위쪽 폴더의 `AGENTS.override.md`, 실제 `CODEX_HOME`을 확인합니다. Claude Code에서는 여러 지침의 충돌을 점검하고 문서의 `/context all`, `/memory` 안내를 참고합니다.

6. 증상: 같은 파일인데 요청을 바꾸면 표식이 사라집니다. 원인 후보: 요청 문구가 지침과 충돌합니다. 확인: “숫자만 답하세요”처럼 출력 형식을 제한하는 문구를 빼고 비교합니다. Codex에서는 지침 요약 요청으로 규칙 내용을 말하는지도 확인합니다.

## 이 실험으로 알 수 없는 것

각 조건은 한 번씩 실행했고 Linux 한 환경과 지정한 모델만 사용했습니다. 반복 실행이나 다른 모델에서도 같은 결과가 나오는지는 알 수 없습니다. 파일 이름의 대소문자를 구분하지 않는 운영체제도 시험하지 않았습니다.

개인 위치의 지침과 `CLAUDE.local.md`는 직접 확인하지 않았으며 `.claude/rules`도 범위에서 뺐습니다. `project_doc_fallback_filenames` 설정 역시 시험하지 않았습니다. Claude Code에 지침 요약 질문을 보내는 확인도 하지 않았습니다.
