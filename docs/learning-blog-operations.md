# 기술 학습 블로그 운영

대상: https://jacks-aiblog.tistory.com/

작은 독립 예제를 실행하고 코드·실제 출력·공식 문서·한계를 묶어 기록한다. 한 편은 하나의 질문에 답한다. 익히지 않은 기술을 실무 경력으로 표현하거나 측정하지 않은 개선 수치를 쓰지 않는다.

## 원고 준비

등록된 실습과 설명은 `labs/learning_basics.py`와 `scripts/prepare_learning_posts.py`에 있다. 다음 명령은 실습을 실행하고 실제 출력과 코드를 원고에 넣는다.

도구 사용 안내와 프로젝트 설명은 `kind: guide`로 등록한다. 확인일·실행한 범위·공식 출처 두 개 이상·표지를 함께 기록한다. 안내 글에 실행하지 않은 실습 식별자를 붙이지 않는다. `catalogue.json`의 순서가 발행 순서이며, 기존 실습 원고도 보존한다. 실습 준비 스크립트는 기존 일곱 실습을 갱신하면서 안내 글의 순서와 표지 정보를 보존한다.

원고는 짧은 도입 뒤 비교표, 실제 입력과 결과, 다른 작업에 적용할 방법을 배치한다. 한 절의 긴 설명을 표나 그림으로 나눌 때는 정보가 추가되는지 확인한다. 장식용 이미지로 분량을 채우지 않는다. 표는 Markdown 표, 그림은 `![설명](asset:flow)`로 넣고 목록의 `assets`에 저장소 내부 PNG 경로를 등록한다. 외부 이미지와 임의 HTML은 받지 않는다.

표지는 흰 바탕·파란 세로선·짧은 주제 두 줄·블로그 이름을 유지한다. 1280×720 이미지의 가운데 720px 안에 문구를 넣어 정사각형 목록에서도 읽히게 한다. 표지 문구와 흐름 그림 단계는 목록에 저장하며, 생성할 때는 Pillow와 NanumGothic 서체가 필요하다. 일일 발행에는 이 생성 패키지를 사용하지 않는다.

```bash
python3 scripts/build_post_assets.py
```

```bash
python3 scripts/prepare_learning_posts.py
python3 -m unittest discover -s tests -v
```

원고·실습 변경을 검토하고 공개 저장소의 기본 브랜치에 반영한 뒤에만 발행할 수 있다. 실행 코드와 원고가 다르거나 공식 출처가 없으면 발행하지 않는다. 앞으로의 소재는 실제로 배운 내용과 해결한 문제에서 추가한다. 단순 정의 나열이나 다른 글의 요약으로 재고를 채우지 않는다.

## 발행 구성

- 한국 시각 매일 07:30에 하루 최대 한 편 실행한다(2026-11-17부터. 시각을 정한 근거는 `docs/design/specs/2026-11-16-publish-time.md`).
- 기존 자동화의 암호화된 로그인 세션을 읽기만 한다. 로그인·추가 인증을 자동 시도하지 않는다.
- 기존 금융 발행기와 일정·이력·콘텐츠 처리 경로를 분리한다.
- 원고는 `docs/posts/catalogue.json` 순서로 고른다. 발행 후 원고 해시·날짜·URL을 기록한다.
- 실습 글에는 고정 코드·테스트 링크, 안내 글에는 고정 원문 링크를 덧붙인다.
- 표지와 그림은 편집기의 사진 첨부로 업로드하고 실제 이미지 주소를 확인한다. 대표 이미지는 공개 글의 첫 이미지와 대조한다.
- 발행 전 처리 중 상태를 저장한다. 결과가 불확실하면 다음 날도 자동 재발행하지 않는다.
- 재고가 없으면 보류한다. 근거 없는 새 글을 임의로 만들지 않는다.

환경 변수 `BLOG_AUTOMATION_ROOT`는 기존 자동화 프로젝트, `TECH_BLOG_STATE_DIR`는 새 블로그의 발행 상태 디렉터리를 가리킨다. 비밀 값은 공개 저장소에 넣지 않는다. 실행 환경에는 기존 세션 복호화에 쓰는 패키지와 Playwright 및 Chromium이 필요하다.

### 로그인 유지

기존 서버의 `blog-automation.service`가 로그인 유지를 담당한다. 매시간 관리자 화면에 접속해 세션을 확인하고, 한국 시각 02:00·06:50·20:00에는 영구 크롬 프로필을 이용해 쿠키를 갱신한다. 프로필의 로그인이 풀렸어도 저장된 세션이 유효하면 쿠키를 주입해 복구한다.

새 블로그 발행기는 실행할 때마다 기존 운영 디렉터리의 `data/sessions/tistory.session`을 복호화해 읽는다. 세션을 별도로 복사하지 않으므로 기존 서버가 갱신한 쿠키를 다음 실행에 바로 사용한다. `blog-automation.service`와 `technical-blog.timer`를 함께 활성화해 두어야 한다. PC·WSL이 꺼져 있으면 세션 확인과 갱신도 실행되지 않는다.

정기 접속만으로 로그인 유지 기간을 보장할 수는 없다. 저장 세션까지 만료되면 카카오 로그인과 추가 인증은 사람이 직접 진행한다. 기존 로그인 스크립트는 비밀번호 자동 입력과 가상 화면을 사용하므로 직접 로그인할 창을 여는 용도로 실행하지 않는다. 수동 인증을 다시 해야 할 때는 화면에 보이는 크롬에서 로그인하고, 새 블로그 관리 화면 접근을 확인한 다음 암호화된 세션을 갱신한다. 쿠키·비밀번호는 문서나 공개 저장소에 저장하지 않는다.

```bash
python3 -m automation.learning_blog --dry-run
systemctl --user status technical-blog.timer
systemctl --user status technical-blog.service
journalctl --user -u technical-blog.service -n 30
```

설치할 단위 파일은 `deploy/`에 있다. 이 PC와 사용자 서비스가 실행 중이고 네트워크·유효한 로그인 세션이 있어야 발행할 수 있다. 부팅 후 밀린 일정이 실행돼도 한국 날짜 기준의 중복 검사를 거친다.

## 실패 확인

`state.json`에 pending이 남아 있으면 먼저 실제 블로그와 관리 화면에서 같은 제목·내용의 글이 존재하는지 확인한다. 이미 발행된 글은 URL과 본문을 확인해 기록을 복구한다. 존재하지 않는 것이 확실할 때만 상태를 정리하고 재시도한다. 손상된 파일을 빈 상태로 자동 초기화하지 않는다.

`status.json`은 마지막 실행 결과, 상태 파일은 완료·확인 대기 원고를 담는다. 성공한 HTTP 응답만으로 발행 성공을 판단하지 않는다. 공개 화면의 식별자·제목·본문·코드블록·표의 행과 셀·이미지 설명·이미지 주소·대표 이미지를 대조한다. 새 확인 대기 기록에는 본문 검증값을 함께 저장해 복구 때도 본문 잘림과 이미지 누락을 확인한다. 기존 기록에는 이 검증값이 없을 수 있다.

이미 발행된 글의 공개 본문을 재검증하고 기록을 복구할 때는 다음 명령을 사용한다.

```bash
python3 -m automation.learning_blog --confirm-url https://jacks-aiblog.tistory.com/글번호
```

관리 화면에서 같은 원고가 없음을 직접 확인했고 아직 공개 주소도 기록되지 않은 경우에만 다음 명령으로 확인 대기를 해제할 수 있다. URL이 있는 기록은 이 명령으로 지울 수 없다. 확인 복구한 날짜에도 새 글을 추가로 발행하지 않도록 처리한다.

```bash
python3 -m automation.learning_blog --clear-pending --confirmed-not-published
```

## 학습과 반응 평가

처음에는 학습 완성도와 재현성을 우선한다. 매주 실행 가능한 글, 본인이 설명할 수 있는 글, 정정이 필요했던 글과 준비 시간을 확인한다. 검색 관리도구를 연결한 뒤에는 색인·관련 검색어·노출·클릭을 함께 관찰한다. 8주를 첫 점검 시점으로 삼되 검색 성장이나 취업·수익을 보장하는 기간으로 해석하지 않는다.

GitHub의 실제 코드·문서 변경과 RSS 봇의 프로필 갱신은 구분한다. 예약 발행일에 맞춘 빈 커밋이나 날짜 조작을 하지 않는다. 경력 문장에는 확인된 직접 기여와 실제 결과만 사용한다.

## 화면 관리

화면 구성은 `automation/technical_skin.py`와 같은 이름의 CSS·JS 파일에 있다. Odyssey의 글·검색·카테고리·댓글 치환자는 보존한다. 블로그 이름과 작성자 표시는 Jack의 AI 개발노트다. 짧은 소개·GitHub 실습 코드·프로필 다음에 최근 기록을 표시하며, 상단 메뉴에서 전체 글·주제·공개 코드·RSS로 이동한다. 현재 화면 기준은 `docs/design/2026-11-15-jack-ai-blog.md`에 있다.

사이드바에는 Jack 소개·주제별 기록·최근 글을 배치한다. 최근 글 위젯은 홈에서만 숨긴다. 실제 집계가 0인 주제는 화면에서 숨기며, 집계 형식이 불명확하면 유지한다. 관리 카테고리는 삭제하지 않는다. 대표 이미지가 없는 글에는 제목·분류로 만든 텍스트 표지를 표시한다. 현재 한국 시간과 파일 경로 주제에는 짧은 핵심어를 쓰고, 나머지 글은 원래 제목을 사용한다. 본문의 목차는 소제목이 세 개 이상일 때 접힌 상태로 표시하며, 코드 복사 권한이 없으면 코드를 선택해 직접 복사하도록 안내한다. 스킨을 수정하기 전에는 현재 HTML·CSS와 설정을 비공개 운영 디렉터리에 백업한다.

화면 변경 시에는 다음 점검을 함께 실행한다.

```bash
python3 -m unittest discover -s tests -v
node tests/check_skin_widgets.js
```

## 8주 운영 기준 (2026-11-15 설정)

하루 최대 한 편은 상한이지 목표가 아니다. 재현하고 확인한 글만 발행하고, 확인하지 못한 날은 발행하지 않는다.

- 분류: AI 시작하기 / 도구·모델 비교 / 프로젝트 적용기 / Python·자동화. 새 글의 비율은 시작하기 40%, 비교 20%, 적용기 30%, Python 10%를 기준으로 한다. 오류 해결 글은 해당 분류에 포함한다.
- 쓰기 전 확인: 실제 질문이 있는지, 기존 설명에 빈틈이 있는지, 직접 재현할 수 있는지를 확인한다. 쓸 수 있는 소재와 읽고 싶은 소재는 다르다.
- 제목: 제품명, 환경, 해결할 문제를 구체적으로 적는다.
- 비교 글: 같은 과제, 같은 환경, 성공 기준, 비용, 반복 횟수를 먼저 정하고 쓴다. 가격과 설정 글은 확인일을 적고 정해진 주기로 다시 확인한다.
- 설치 글: 새 환경에서 설치·첫 요청을 직접 수행하지 않은 범위는 본문에 그렇게 적는다.
- 매주 확인: 글·검색어별 노출·클릭·클릭률·색인 상태, 실제 읽은 방문(참여 세션), 다음 글·저장소 이동, 글 하나를 만들고 갱신하는 데 든 시간. 전체 조회수만 보고 판단하지 않는다.
- 수정 기준: 색인된 지 4주가 넘었는데 노출이 거의 없으면 수요와 색인을 먼저 점검한다. 비슷한 검색어·순위에서 클릭률이 낮으면 제목과 도입을 고친다.
- 보류 기준: 같은 주제를 두 번 고쳐도 8주 동안 검색·독자 반응이 없으면 그 연재를 보류한다. 재현 실패나 중대한 오류는 즉시 발행을 멈추고 정정한다. 적은 표본으로 블로그 전체를 판단하지 않는다.
- 이전 금융 블로그의 교훈: 글 수가 늘어도 실제 독자가 늘지 않았다. 수집봇이 조회수를 부풀렸으므로 참여 세션을 기준으로 본다.
